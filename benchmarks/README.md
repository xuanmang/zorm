# ZORM 性能基准测试

本目录包含 ZORM 的性能基准测试,用于验证项目的性能目标。

## 性能目标

根据 PRD,ZORM 的性能目标是:

1. **查询构建开销**: < 1ms (comptime 优化)
2. **运行时开销**: < 5% (与原生 SQL 相比)
3. **批量操作**: 1000 行插入 < 5ms

## 运行基准测试

```bash
# 运行所有基准测试
zig build bench

# 查看详细结果
cat benchmarks/results/latest.txt
```

## 基准测试项目

### 1. 查询构建性能 (`query_builder_bench.zig`)

测试查询构建器的性能:
- 简单 SELECT 查询
- 复杂 JOIN 查询
- 批量 INSERT 查询

**验收标准**:
- 简单查询: < 1ms
- 复杂查询: < 1ms
- 批量插入 (1000 行): < 5ms

### 2. 内存分配基准测试 (规划中)

测试内存分配模式:
- 查询构建器内存使用
- 结果扫描内存开销
- 临时缓冲区管理

### 3. 端到端性能基准测试 (规划中)

需要真实数据库连接:
- 完整查询执行流程
- 事务处理性能
- 钩子系统开销

## 结果解读

- **✅ 通过**: 平均耗时 < 目标值
- **❌ 未达标**: 平均耗时 >= 目标值

## 性能优化建议

如果基准测试未达标,可以考虑:

1. **查询构建优化**:
   - 减少不必要的内存分配
   - 使用 `ArrayList` 的 `ensureTotalCapacity()` 预分配
   - 优化字符串拼接逻辑

2. **Comptime 优化**:
   - 更多逻辑移到编译时
   - 使用 `comptime` 字段反射
   - 减少运行时分支

3. **内存管理优化**:
   - 使用 Arena Allocator 批量释放
   - 减少临时分配
   - 复用缓冲区

## 持续改进
