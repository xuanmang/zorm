### 关系类型定义

[Source: ORM 设计模式]

#### 1. Belongs-To (多对一)
- **定义**: 子表的每条记录属于父表的一条记录
- **示例**: Post belongs to User (post.user_id -> user.id)
- **外键**: 子表包含父表的主键

#### 2. Has-Many (一对多)
- **定义**: 父表的一条记录拥有子表的多条记录
- **示例**: User has many Posts
- **外键**: 子表包含父表的主键

#### 3. Many-to-Many (多对多)
- **定义**: 两个表通过中间表建立多对多关系
- **示例**: Post <-> Tags (通过 post_tags)
- **中间表**: 包含两个外键

### N+1 查询问题详解

[Source: 性能优化最佳实践]

#### 问题描述

```zig
// ❌ N+1 查询问题
// 1 次查询 users
var users = try db.newSelect(User).scan(&user_list);

// N 次查询 posts (每个 user 一次)
for (users.items) |user| {
    var posts = try db.newSelect(Post)
        .where("user_id = ?", .{user.id})
        .scan(&post_list);
    // 总查询次数 = 1 + N
}
```

#### 解决方案: 预加载

```zig
// ✅ 预加载 - 只需 1 次查询
var results = try db.newSelect(User)
    .column("users.*")
    .column("posts.id as post_id")
    .column("posts.title as post_title")
    .leftJoin("posts", "posts.user_id = users.id")
    .scan(&result_list);

// 在代码中分组
var user_posts = try groupByUserId(allocator, results);
```

### ZORM API 引用

#### JOIN 查询
[Source: docs/functional_spec.md - 2.2.1 SELECT 查询]

```zig
// Belongs-To: Post -> User
var query = try db.newSelect(Post);
try query
    .column("posts.*")
    .column("users.name as author_name")
    .column("users.email as author_email")
    .leftJoin("users", "users.id = posts.user_id")
    .where("posts.id = ?", .{post_id});

// Has-Many: User -> Posts
var query = try db.newSelect(User);
try query
    .column("users.*")
    .column("COUNT(posts.id) as post_count")
    .leftJoin("posts", "posts.user_id = users.id")
    .groupBy("users.id");

// Many-to-Many: Post <-> Tags
var query = try db.newSelect(Post);
try query
    .column("posts.*")
    .column("tags.id as tag_id")
    .column("tags.name as tag_name")
    .innerJoin("post_tags", "post_tags.post_id = posts.id")
    .innerJoin("tags", "tags.id = post_tags.tag_id")
    .where("posts.id = ?", .{post_id});
```

### 分组辅助函数

```zig
/// 将平面结果分组为嵌套结构
pub fn groupByUserId(
    allocator: Allocator,
    flat_results: []const FlatResult,
) !std.AutoHashMap(i64, UserWithPosts) {
    var grouped = std.AutoHashMap(i64, UserWithPosts).init(allocator);
    
    for (flat_results) |result| {
        var entry = try grouped.getOrPut(result.user_id);
        if (!entry.found_existing) {
            entry.value_ptr.* = .{
                .user = result.user,
                .posts = std.ArrayList(Post).init(allocator),
            };
        }
        try entry.value_ptr.posts.append(allocator, result.post);
    }
    
    return grouped;
}
```

### 性能优化建议

[Source: 数据库性能最佳实践]

1. **始终使用预加载加载关联数据**: 避免 N+1 查询
2. **选择需要的列**: 减少数据传输 (不要 SELECT *)
3. **使用 INNER JOIN vs LEFT JOIN**: 根据业务需求选择
4. **索引外键列**: 提升 JOIN 性能
5. **分页加载大量关联数据**: 避免内存溢出

```zig
test "Belongs-To relationship" {
    const allocator = testing.allocator;
    const db = try zorm.DB.initMock(allocator, .postgresql);
    defer db.deinit();
    
    var query = try db.newSelect(Post);
    defer query.deinit();
    
    try query
        .column("posts.*")
        .column("users.name as author_name")
        .leftJoin("users", "users.id = posts.user_id");
    
    const sql = try query.buildSQL();
    defer allocator.free(sql);
    
    try testing.expect(std.mem.containsAtLeast(u8, sql, 1, "LEFT JOIN users"));
}

test "N+1 vs Eager Loading - query count" {
    const allocator = testing.allocator;
    const db = try zorm.DB.initMockWithStats(allocator, .postgresql);
    defer db.deinit();
    
    // N+1 方式
    db.resetStats();
    // ... 执行 N+1 查询
    const n_plus_1_queries = db.getStats().queries;
    
    // Eager Loading 方式
    db.resetStats();
    // ... 执行预加载
    const eager_queries = db.getStats().queries;
    
    // 验证查询次数
    try testing.expect(eager_queries < n_plus_1_queries);
}
```
