### 重要约束: 使用 ZORM API, 禁止直接使用 pg.zig

**核心原则**: 本 Story 的所有示例代码必须通过 ZORM 的公共 API 与数据库交互,**严禁直接导入和使用 pg.zig 包**。

**允许的做法**:
```zig
const zorm = @import("zorm");
const db = try zorm.DB.init(allocator, conn, .postgresql, .{});

// 聚合查询
var query = try db.newSelect(Post);
try query.column("COUNT(*) as total");
```

**禁止的做法**:
```zig
const pg = @import("pg");  // ❌ 禁止直接导入 pg.zig
```

#### 基础聚合函数

```zig
// COUNT
var query = try db.newSelect(User);
try query.column("COUNT(*) as total");
const result = try query.scanOne();
std.log.info("Total users: {d}", .{result.total});

// SUM
var query = try db.newSelect(Order);
try query.column("SUM(amount) as total_amount");
const result = try query.scanOne();

// AVG
var query = try db.newSelect(Post);
try query.column("AVG(LENGTH(content)) as avg_length");

// MIN / MAX
var query = try db.newSelect(User);
try query.column("MIN(age) as min_age, MAX(age) as max_age");
```

#### GROUP BY 分组聚合

```zig
// 单列分组
var query = try db.newSelect(Post);
try query
    .column("user_id")
    .column("COUNT(*) as post_count")
    .column("AVG(LENGTH(content)) as avg_length")
    .groupBy("user_id");

// 多列分组
var query = try db.newSelect(Post);
try query
    .column("user_id, status")
    .column("COUNT(*) as count")
    .groupBy("user_id, status");

// HAVING 过滤
var query = try db.newSelect(Post);
try query
    .column("user_id")
    .column("COUNT(*) as post_count")
    .groupBy("user_id")
    .having("COUNT(*) > ?", .{5});
```

#### ROLLUP 和 CUBE (PostgreSQL)

```zig
// ROLLUP - 生成小计和总计
const sql =
  \\SELECT
  \\  status,
  \\  user_id,
  \\  COUNT(*) as cnt,
  \\  SUM(LENGTH(content)) as total_length
  \\FROM posts
  \\GROUP BY ROLLUP(status, user_id);

try db.newRaw(sql, .{}).exec();

// 结果示例:
// status    user_id  cnt  total_length
// active    1        10   5000
// active    2        15   7500
// active    NULL     25   12500  <- status 小计
// inactive  1        5    2000
// inactive  NULL     5    2000   <- status 小计
// NULL      NULL     30   14500  <- 总计

// CUBE - 多维度汇总
const sql =
  \\SELECT
  \\  status,
  \\  category,
  \\  COUNT(*) as cnt
  \\FROM posts
  \\GROUP BY CUBE(status, category);

try db.newRaw(sql, .{}).exec();

// GROUPING SETS - 自定义分组
const sql =
  \\SELECT
  \\  status,
  \\  user_id,
  \\  COUNT(*) as cnt
  \\FROM posts
  \\GROUP BY GROUPING SETS (
  \\  (status, user_id),
  \\  (status),
  \\  (user_id),
  \\  ()
  \\);

try db.newRaw(sql, .{}).exec();
```

#### 聚合与窗口函数结合

```zig
const sql =
  \\SELECT
  \\  user_id,
  \\  status,
  \\  COUNT(*) as cnt,
  \\  SUM(COUNT(*)) OVER (PARTITION BY status) as status_total,
  \\  ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY status), 2) as pct
  \\FROM posts
  \\GROUP BY user_id, status;

try db.newRaw(sql, .{}).exec();
```

## 常见问题

### Q1: 连接失败 (Connection refused)

**问题**: `error: ConnectionFailed: could not connect to server`

**解决方案**:
1. 确认 PostgreSQL 服务正在运行:
   ```bash
   # macOS
   brew services list | grep postgresql

   # Linux
   sudo systemctl status postgresql
   ```

2. 检查连接参数 (examples/common/db_config.zig):
   ```zig
   host: []const u8 = "127.0.0.1",
   port: u16 = 5432,
   user: []const u8 = "pguser",
   password: []const u8 = "Pg#123!",
   database: []const u8 = "zorm_examples",
   ```

### Q2: 编译错误 (libpq not found)

**问题**: `error: unable to find libpq`

**解决方案**:
```bash
# macOS
export LIBRARY_PATH=/opt/homebrew/opt/libpq/lib:$LIBRARY_PATH
export CPATH=/opt/homebrew/opt/libpq/include:$CPATH

# Linux
sudo apt-get install libpq-dev
```

### Q3: 运行时错误 (Segmentation fault)

**问题**: 运行时崩溃

**解决方案**:
1. 检查内存管理:
   ```zig
   var list: std.ArrayList(T) = .{};
   defer list.deinit(allocator);  // 确保释放内存
   ```

2. 使用调试模式:
   ```bash
   zig build run-example -Dexample=01 -Doptimize=Debug
   ```

### Q4: 内存泄漏调试

**问题**: 内存未正确释放

**解决方案**:
```zig
// 使用 GeneralPurposeAllocator 检测泄漏
var gpa = std.heap.GeneralPurposeAllocator(.{}){};
defer {
    const leaked = gpa.deinit();
    if (leaked == .leak) {
        std.log.err("Memory leak detected!", .{});
    }
}
const allocator = gpa.allocator();
```

### Q5: PostgreSQL 版本兼容性

**问题**: 某些功能不可用

**解决方案**:
- ROLLUP/CUBE: 需要 PostgreSQL 9.5+
- JSONB: 需要 PostgreSQL 9.4+
- ON CONFLICT: 需要 PostgreSQL 9.5+

检查版本:
```bash
psql -U postgres -c "SELECT version();"
```
