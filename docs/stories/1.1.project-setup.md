### DB 核心 API 设计
[Source: docs/architecture/architecture-core.md#1-db-数据库实例]

```zig
pub const DB = struct {
    allocator: Allocator,
    conn: *Connection,
    dialect: Dialect,
    hooks: ?*QueryHook,
    stats: ConnectionStats,

    /// 初始化数据库实例
    pub fn init(allocator: Allocator, conn: *Connection, dialect: Dialect, opts: DBOptions) !DB;

    /// 关闭数据库连接
    pub fn deinit(self: *DB) void;
};

pub const DBOptions = struct {
    max_open_conns: usize = 10,
    max_idle_conns: usize = 5,
    conn_max_lifetime: i64 = 3600, // 秒
    debug: bool = false,
};
```

**关键设计要点**:
- DB 结构体管理整个连接生命周期
- 单一 DB 实例对应一个 PostgreSQL 连接
- 连接池参数在 v1.0 主要用于配置保留，实际连接池管理在 v2.0 实现
- Dialect 字段为 `.postgresql`（当前仅支持 PostgreSQL）

### 内存管理规范
[Source: docs/architecture/coding-standards.md#内存管理规范]

**强制要求**:
1. 所有 API 必须接受 `std.mem.Allocator` 参数（显式内存管理）
2. 所有资源必须提供 `deinit()` 方法
3. 使用 `defer` 确保资源释放
4. 使用 `errdefer` 处理错误路径的清理

**ArrayList API (Zig 0.15.2+)**:
```zig
// ✅ 正确 (Zig 0.15.2+)
var list: std.ArrayList(T) = .{};
defer list.deinit(allocator);

// ❌ 错误 (旧版 API)
var list = std.ArrayList(T).init(allocator); // ❌
defer list.deinit(); // ❌ 缺少 allocator 参数
```

### 错误处理规范
[Source: docs/architecture/coding-standards.md#错误处理规范]

**强制要求**:
1. 所有可能失败的操作返回 `!T` error union
2. 使用 `try` 传播错误
3. 避免 `catch` 吞没错误（除非有明确处理逻辑）

**自定义错误类型** (src/error.zig):
```zig
pub const ZormError = error{
    ConnectionClosed,    // 数据库连接已关闭
    InvalidConfig,       // 无效的配置参数
    // ... 其他错误
};
```

### pg.zig 驱动集成
[Source: docs/architecture/tech-stack.md#必需依赖]

**集成步骤**:
1. 在 build.zig.zon 中添加 pg.zig 依赖
2. 或使用 Git submodule: `git submodule add https://github.com/karlseguin/pg.zig deps/pg`
3. 在 build.zig 中配置模块引用
4. 在 src/core/connection.zig 中封装 pg.zig 连接逻辑

**pg.zig 关键 API**:
- `pg.Pool.init()` - 创建连接池
- `pool.acquire()` - 获取连接
- `conn.exec()` - 执行 SQL
- `conn.deinit()` - 释放连接
