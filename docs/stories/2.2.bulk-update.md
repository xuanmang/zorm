# Story 2.2: Bulk UPDATE Support

**Epic**: 2 - Complete CRUD & Transaction Support
**Story**: 2.2
**Status**: Approved

---

## Story

**As a** Zig developer,
**I want** 批量更新多行数据,
**so that** 我能够高效地修改大量记录而不需要循环执行单个更新。

---

## Acceptance Criteria

1. **AC2.2.1**: UPDATE 构建器支持复杂 WHERE 条件匹配多行
2. **AC2.2.2**: 支持 `.whereIn(column, values)` 方法批量匹配（如 `WHERE id IN (1,2,3)`）
3. **AC2.2.3**: 支持使用子查询作为 WHERE 条件
4. **AC2.2.4**: 批量更新的 RETURNING 子句返回所有更新行的数据
5. **AC2.2.5**: 完整使用示例验证批量更新工作流程

## Dev Notes

### 架构参考

**批量操作设计** [Source: architecture/architecture-core.md#Performance Optimization]:
- 批量操作显著减少网络往返
- 单条 SQL 更新多行比循环单行更新快 10-100 倍
- 使用 WHERE IN 或复杂条件匹配多行

**SQL 生成规则** [Source: architecture/coding-standards.md#禁止规则]:
- ❌ 禁止字符串拼接 SQL
- ✅ WHERE IN 参数必须通过占位符绑定
- ✅ 子查询参数合并到主查询参数列表

**性能优化** [Source: architecture/architecture-core.md#Memory Optimization]:
- Arena Allocator 用于临时分配
- 预分配 ArrayList 容量
- 避免不必要的数据拷贝

### WHERE IN 实现细节

**参数展开**:
```zig
// 输入
const user_ids = [_]i64{ 1, 2, 3, 5, 8 };
try update.whereIn("id", &user_ids);

// 生成的 SQL
UPDATE users SET status = $1 WHERE id IN ($2, $3, $4, $5, $6)

// 参数数组
[status_value, 1, 2, 3, 5, 8]
```

**占位符编号**:
- SET 子句参数先编号: $1, $2, ...
- WHERE 子句参数后编号: $N+1, $N+2, ...
- WHERE IN 展开多个占位符

### 子查询支持

**子查询接口** [Source: architecture/architecture-core.md#Subquery Support]:
```zig
// 创建子查询
var subquery = try db.newSelect(Post);
defer subquery.deinit();
try subquery
    .column("DISTINCT user_id")
    .where("published = ?", .{true});

// 在主查询中使用
var update = try db.newUpdate(User);
defer update.deinit();
try update
    .set("verified = ?", .{true})
    .whereInSubquery("id", subquery)
    .exec();

// 生成的 SQL
UPDATE users
SET verified = $1
WHERE id IN (SELECT DISTINCT user_id FROM posts WHERE published = $2)
```

### Bun ORM 对齐

**API 一致性** [Source: prd.md#Background Context]:
```zig
// ZORM (Zig)
const user_ids = [_]i64{ 1, 2, 3, 5, 8 };
const result = try db.newUpdate(User)
    .set("status = ?", .{"verified"})
    .whereIn("id", &user_ids)
    .exec();

// Bun ORM (TypeScript)
const userIds = [1, 2, 3, 5, 8];
const result = await db.update(User)
    .set({ status: "verified" })
    .whereIn("id", userIds)
    .exec();
```

### Testing

**测试标准** [Source: architecture/coding-standards.md#测试规范]:
- **测试文件位置**: `tests/unit/bulk_update_test.zig`
- **测试命名**: `test "BulkUpdate: {描述性名称}"`
- **内存泄漏检测**: 使用 `std.testing.allocator`
- **覆盖率目标**: ≥ 80%

**性能基准测试** [Source: architecture/tech-stack.md#Performance Benchmarks]:
- 对比批量 UPDATE vs 循环单行 UPDATE
- 目标：批量更新至少快 10 倍
- 使用 `std.time.Timer` 测量执行时间

**集成测试场景**:
1. WHERE IN 更新 10 行
2. WHERE IN 更新 1000 行
3. 子查询条件更新
4. 复杂条件组合更新
5. 批量更新 + RETURNING 返回所有行

### 错误处理

**常见错误场景**:
- 空 values 数组 → 返回 error.EmptyWhereIn
- 子查询参数冲突 → 自动合并和重新编号
- WHERE IN 超过数据库限制 → 文档说明分批策略
