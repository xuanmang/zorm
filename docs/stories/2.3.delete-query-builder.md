# Story 2.3: Type-Safe DELETE Query Builder

**Epic**: 2 - Complete CRUD & Transaction Support
**Story**: 2.3
**Status**: Ready for Review

---

## Story

**As a** Zig developer,
**I want** 使用类型安全的 DELETE 构建器删除数据库记录,
**so that** 我能够安全地删除数据，并通过 WHERE 条件防止误删。

---

## Acceptance Criteria

1. **AC2.3.1**: 提供 `db.newDelete(T)` API 创建 DELETE 查询构建器
2. **AC2.3.2**: 强制要求 WHERE 条件（防止意外删除所有行），无 WHERE 时编译错误或返回错误
3. **AC2.3.3**: 支持 `.where(condition, args)` 方法指定删除条件
4. **AC2.3.4**: 提供 `.exec()` 方法执行删除，返回 `DeleteResult`（包含 rows_affected）
5. **AC2.3.5**: 支持 `.setReturning(cols)` 方法启用 RETURNING 子句，返回被删除的数据
6. **AC2.3.6**: 提供 `.execReturning(dest)` 方法执行删除并获取被删除的数据
7. **AC2.3.7**: 支持 `.whereIn()` 批量删除
8. **AC2.3.8**: 完整使用示例验证工作流程

## Dev Notes

### 架构参考

**DeleteQuery 设计** [Source: architecture/architecture-core.md#Query Builders]:
- 遵循与 SelectQuery/UpdateQuery 相同的 Builder Pattern
- 支持 Fluent Interface（链式调用返回 *Self）
- **安全优先**: 强制要求 WHERE 条件防止误删所有行

**安全设计** [Source: architecture/architecture-core.md#Security Design]:
- DELETE without WHERE 是危险操作
- 必须显式提供 WHERE 条件
- 如需无条件删除，使用 `db.newRaw("DELETE FROM table")`

**PostgreSQL RETURNING** [Source: prd.md#FR5]:
- 删除前返回被删除的数据
- 用于审计日志或确认删除内容
- 示例：`DELETE FROM users WHERE id = $1 RETURNING *`

### 强制 WHERE 检查实现

**实现策略**:
```zig
pub fn exec(self: *Self) !DeleteResult {
    if (!self.has_where) {
        return error.MissingWhereClause;
    }
    const sql = try self.build();
    // ... 执行查询
}
```

**错误消息**:
```
error.MissingWhereClause: DELETE requires WHERE clause for safety.
To delete all rows, use: db.newRaw("DELETE FROM {table}")
```

**可选的 Escape Hatch** (如果用户强烈需要):
```zig
pub fn unsafeExecAll(self: *Self) !DeleteResult {
    // 允许无 WHERE 删除，但方法名明确警告危险
    const sql = try self.build();
    // ... 执行查询
}
```

### Bun ORM 对齐

**API 一致性** [Source: prd.md#Background Context]:
```zig
// ZORM (Zig)
const result = try db.newDelete(User)
    .where("id = ?", .{123})
    .exec();

// ZORM (Zig) - 审计日志场景
var deleted_users: std.ArrayList(User) = .{};
defer deleted_users.deinit(allocator);

try db.newDelete(User)
    .where("status = ?", .{"inactive"})
    .setReturning("*")
    .execReturning(&deleted_users);

// 记录被删除的用户
for (deleted_users.items) |user| {
    std.debug.print("Deleted user: {s}\n", .{user.email});
}

// Bun ORM (golang)
var result = await db.delete(User)
    .where({ id: 123 })
    .exec();

var deletedUsers = db.delete(User)
    .where({ status: "inactive" })
    .returning("*")
    .exec();
```

### 错误处理

**自定义错误类型** [Source: architecture/coding-standards.md#错误处理]:
```zig
pub const ZormError = error{
    MissingWhereClause,  // DELETE without WHERE
    NoRows,              // 删除无匹配行
    // ... 其他错误
};
```

**错误场景**:
- 无 WHERE 条件 → error.MissingWhereClause
- WHERE 条件不匹配任何行 → 正常返回（rows_affected = 0）
- 数据库连接错误 → error.ConnectionClosed
- SQL 语法错误 → error.SQLSyntaxError
