## Dev Notes

### 架构参考

**事务隔离级别** [Source: architecture/architecture-core.md#Transaction Management]:
- PostgreSQL 支持四个隔离级别（SQL 标准）
- 默认级别：READ COMMITTED
- 级别越高，一致性越强，但并发性能越低

**PostgreSQL 特性** [Source: prd.md#FR8]:
- READ UNCOMMITTED 在 PostgreSQL 中实际等同于 READ COMMITTED
- PostgreSQL 使用 MVCC 实现隔离级别
- SERIALIZABLE 通过 SSI (Serializable Snapshot Isolation) 实现

### 隔离级别详解

**READ UNCOMMITTED** (PostgreSQL 不支持):
- PostgreSQL 会自动升级为 READ COMMITTED
- 文档中需要说明这一行为

**READ COMMITTED** (默认):
- 查询只能看到事务开始前已提交的数据
- 同一事务内的重复查询可能看到不同结果（Non-repeatable Read）
- 适用场景：大多数 OLTP 应用

**REPEATABLE READ**:
- 事务内的查询看到一致性快照
- 避免 Non-repeatable Read
- 仍可能出现 Phantom Read（PostgreSQL MVCC 实际避免了）
- 适用场景：需要一致性读的报表或分析

**SERIALIZABLE**:
- 最高隔离级别，完全避免并发异常
- 通过检测读写冲突实现
- 可能导致事务串行化错误（需要重试）
- 适用场景：金融系统、关键业务逻辑

### 实现细节

**IsolationLevel 枚举定义**:
```zig
pub const IsolationLevel = enum {
    read_uncommitted,  // PostgreSQL 实际等同于 read_committed
    read_committed,    // PostgreSQL 默认
    repeatable_read,
    serializable,

    /// 转换为 SQL 语句
    pub fn toSQL(self: IsolationLevel) []const u8 {
        return switch (self) {
            .read_uncommitted => "READ UNCOMMITTED",
            .read_committed => "READ COMMITTED",
            .repeatable_read => "REPEATABLE READ",
            .serializable => "SERIALIZABLE",
        };
    }
};
```

**TxOptions 结构体定义**:
```zig
pub const TxOptions = struct {
    isolation_level: ?IsolationLevel = null,
    // 未来扩展：
    // read_only: bool = false,
    // deferrable: bool = false,
};
```

**beginTx() 实现**:
```zig
pub fn beginTx(self: *DB, opts: TxOptions) !*Tx {
    if (self.active_tx) |_| {
        return error.NestedTransaction;
    }

    try self.conn.execute("BEGIN", .{});

    // 设置隔离级别（如果指定）
    if (opts.isolation_level) |level| {
        const sql = try std.fmt.allocPrint(
            self.allocator,
            "SET TRANSACTION ISOLATION LEVEL {s}",
            .{level.toSQL()}
        );
        defer self.allocator.free(sql);
        try self.conn.execute(sql, .{});
    }

    const tx = try self.allocator.create(Tx);
    tx.* = Tx{
        .allocator = self.allocator,
        .conn = self.conn,
        .db = self,
        .isolation_level = opts.isolation_level,
        .is_active = true,
        .is_committed = false,
        .is_rolled_back = false,
    };

    self.active_tx = tx;
    return tx;
}
```

### Bun ORM 对齐

**API 一致性** [Source: prd.md#Background Context]:
```zig
// ZORM (Zig)
const tx = try db.beginTx(.{
    .isolation_level = .serializable,
});
errdefer tx.rollback() catch {};

// 执行需要 serializable 级别的操作
// ...

try tx.commit();

// Bun ORM (TypeScript)
const tx = await db.beginTx({
    isolationLevel: "serializable"
});

try {
    // 执行操作
    // ...
    await tx.commit();
} catch (err) {
    await tx.rollback();
    throw err;
}
```

### 性能考虑

**隔离级别性能影响** [Source: architecture/architecture-core.md#Performance Optimization]:
- READ COMMITTED: 最低开销，最高并发
- REPEATABLE READ: 中等开销，一致性快照
- SERIALIZABLE: 最高开销，可能导致事务冲突重试

**建议**:
- 默认使用 READ COMMITTED
- 仅在需要一致性读时使用 REPEATABLE READ
- 仅在关键业务逻辑使用 SERIALIZABLE
- SERIALIZABLE 可能需要应用层重试逻辑
